# Runtime documentation lookup

`joker doc` provides pydoc-style access to the documentation metadata installed in the running Joker runtime.

It is intentionally separate from the static HTML generated by `docs/generate-docs.joke`:

- the CLI renders Markdown by default for terminals and coding agents;
- `--format json` exposes the same query result as structured data;
- `joker doc serve` starts a small local HTTP browser/search UI;
- both frontends read the live namespace/var metadata after normal runtime initialization.

## Commands

```bash
joker doc
joker doc joker.string
joker doc joker.core/first
joker doc search websocket
joker doc --format json joker.core/first
joker doc serve --addr 127.0.0.1:8080
```

## Query behavior

- Empty query lists namespaces.
- Exact namespace queries render namespace documentation and public vars.
- Exact qualified var queries render one var in full.
- Unqualified names and arbitrary text return matching namespaces/vars.
- Duplicate referred vars are collapsed by qualified var name in search results.

## Output formats

Markdown is the default and is optimized for agent use:

~~~markdown
# `joker.core/first`

```clojure
(first coll)
```

Returns the first item in the collection.
~~~

JSON is available for tools:

```bash
joker doc --format json first
```

## Local web UI

```bash
joker doc serve --addr 127.0.0.1:8080
```

The HTTP server exposes:

- `/` — browser UI with a search box;
- `/?q=query` — rendered search results;
- `/api/docs?q=query` — JSON query endpoint.

The server currently renders from the in-memory runtime docs index instead of embedding the static generated HTML tree. This keeps the binary small while still enabling offline browsing.

## Validation

The command is covered by Go tests in `cmd/joker/doc_test.go` and CI-equivalent smoke checks should include:

```bash
go test ./cmd/joker -run 'TestRenderDoc|TestQueryDocs' -count=1
go build -o joker ./cmd/joker
./joker doc joker.core/first
./joker doc --format json joker.core/first
```
